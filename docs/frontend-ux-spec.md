# Frontend UX Spec

## 1. Формат клиентского приложения

Для курсовой клиентская часть разрабатывается как `Vite + vanilla JavaScript + BEM + CSS`.

Рекомендуемый формат:
- многостраничное приложение на статических HTML-страницах;
- каждая страница собирается через Vite;
- общая логика выносится в переиспользуемые JS-модули;
- пользовательские сущности реализуются через классы и модули ES6.

Почему это подходит под задание:
- соответствует стеку `HTML5, CSS3, JavaScript (ES6+)`;
- хорошо сочетается с БЭМ;
- легко публикуется на `GitHub Pages`;
- не требует лишнего фреймворка поверх требований курсовой.

## 2. Набор страниц

Минимальный набор страниц для первой версии фронтенда:

1. `index.html`
   Главная витрина магазина гитар, hero-блок, преимущества, переход в каталог.

2. `catalog.html`
   Основной каталог товаров с карточками, быстрым добавлением в корзину и фильтрацией.

3. `auth.html`
   Единая страница входа и регистрации.

4. `cart.html`
   Страница корзины с изменением количества товаров и переходом к оформлению заказа.

5. `orders.html`
   История заказов пользователя и просмотр статусов.

6. `payment-success.html`
   Экран успешного возврата после оплаты.

7. `payment-fail.html`
   Экран неуспешной оплаты с повторным переходом в корзину или каталог.

## 3. Основные пользовательские сценарии

### 3.1 Гость

1. Открывает главную страницу.
2. Переходит в каталог.
3. Просматривает список товаров.
4. Пытается добавить товар в корзину.
5. При необходимости переходит к авторизации.

### 3.2 Авторизованный пользователь

1. Входит в систему через `auth.html`.
2. Просматривает каталог и добавляет товары в корзину.
3. Изменяет количество товаров в корзине.
4. Создает заказ.
5. Переходит по ссылке на оплату.
6. Возвращается на страницу успеха или ошибки оплаты.
7. Просматривает историю заказов.

### 3.3 Административный сценарий

В рамках первого фронтенд-этапа отдельная admin-панель не делается.
Создание товаров пока остается через API / Postman / curl.

## 6. Адаптивное поведение

Целевые точки:
- mobile: от `320px`
- tablet: от `768px`
- desktop: от `1200px`

Правила:
- mobile-first верстка;
- на мобильных каталог уходит в одну колонку;
- корзина на мобильных становится вертикальной;
- кнопки основных действий должны быть заметными и крупными;
- навигация на маленьких экранах упрощается;
- ключевые CTA всегда доступны без сложных hover-сценариев.

## 7. Визуальное направление

Тема проекта: современный интернет-магазин гитар.

Опорные визуальные идеи:
- теплые древесные оттенки, графитовые акценты, светлый фон;
- крупная выразительная типографика для витрины;
- карточки товаров с акцентом на название, цену и наличие;
- визуально заметные состояния кнопок "в корзину" и "оформить заказ";
- аккуратные состояния загрузки, пустых списков и ошибок.

## 8. Связь с текущим API

Уже доступные сценарии:
- `POST /register`
- `POST /login`
- `GET /products`
- `POST /cart/items`
- `PUT /cart/items/:product_id`
- `DELETE /cart/items/:product_id`
- `GET /cart`
- `DELETE /cart`
- `POST /orders`
- `GET /orders`
- `GET /orders/:id`
- `GET /success`
- `GET /fail`

Вывод:
- MVP фронтенда можно начать без дополнительных backend-изменений;
- каталог, auth, корзина и заказы уже опираются на существующее API;
- визуальные улучшения карточек товаров могут позже потребовать расширения модели товара.
